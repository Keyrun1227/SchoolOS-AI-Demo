## 🌟 Introduction

**SchoolOS AI** is an intelligent academic assessment and learning platform designed to help schools move beyond marks and traditional examination reports.

The platform aims to transform assessment results into actionable learning insights, helping educators identify learning gaps, plan targeted revision, conduct follow-up assessments, and understand academic progress through a structured workflow.

**Our mission:** Help schools make better academic decisions through meaningful assessment data and focused learning support.

## 🎯 The Core Learning Cycle

<p align="center">
  <strong>📝 Assess → 🔍 Analyse → 📚 Revise → 🧪 Retest → 📈 Measure</strong>
</p>

| Stage | Purpose |
|---|---|
| 📝 Assess | Create or manage assessments and capture student performance. |
| 🔍 Analyse | Identify performance patterns and learning gaps from available evidence. |
| 📚 Revise | Focus learning activities on concepts that need additional attention. |
| 🧪 Retest | Evaluate learning through follow-up assessments. |
| 📈 Measure | Compare recorded results to understand progress and remaining learning needs. |

---

## 🏫 Designed for the School Community

### 👨‍💼 Principal Workspace

- Review available academic performance information.
- Understand class and subject performance patterns.
- Identify areas requiring academic attention.
- Support teacher follow-up and academic planning.
- Review available reports and performance summaries.

### 👩‍🏫 Teacher Workspace

- Create or manage assessments through supported workflows.
- Enter and review student marks.
- Analyse question-level and topic-level performance where supported.
- Identify learning gaps using assessment evidence.
- Plan targeted revision and follow-up assessments.
- Compare recorded assessment and retest results.

### 👨‍👩‍👧 Parent Workspace

- Review available assessment results for linked children.
- Understand subject-level performance.
- Follow learning priorities and recorded progress.
- Access reports permitted by the application's authorization rules.

### 🎒 Student Workspace

- Review permitted personal academic information.
- Understand areas requiring additional practice.
- Follow supported revision and retest activities.
- Track recorded progress through available learning workflows.

*Available actions depend on the implemented features, account permissions, and configured data.*

---

## 🧠 Key Features

### 📊 Academic Assessment and Analysis

- Assessment and marks-management workflows.
- Topic-level learning-gap identification where supported.
- Performance summaries based on available records.
- Evidence-based revision recommendations.
- Comparison of recorded assessment and follow-up results.

### 📚 Targeted Revision

SchoolOS AI connects identified learning needs with focused practice. The objective is to help educators determine which concept needs attention, what evidence supports the conclusion, and whether follow-up assessment results show improvement.

### 🤖 AI-Assisted Academic Support

AI can support explanations and learning guidance where the relevant integration and provider are configured. Academic calculations should be based on saved records and deterministic application logic rather than invented model outputs.

### 🎮 SchoolOS Learning Expedition

An educational adventure designed around four missions:

1. **Assessment Lab**
2. **Analysis Observatory**
3. **Revision Garden**
4. **Retest Arena**

The experience uses fictional learning scenarios and complements the core academic workflow.

### 🔐 Role-Based Access

The platform is organised around Principal, Teacher, Parent, and Student experiences. Sensitive data must be protected through server-side authentication and authorization.

## ⚙️ Getting Started

### Prerequisites

- Python compatible with the backend requirements.
- Node.js and npm compatible with the frontend dependencies.
- Git.
- An AI provider API key if testing provider-dependent features.

### 1. Request Source Code Access

The source repository is private. To request access, email:

**[chitturidurgasatyasaikiran@gmail.com](mailto:chitturidurgasatyasaikiran@gmail.com)**

Include your name, organization (if applicable), and purpose of access. Approval is required.

Once access has been granted:

```bash
git clone https://github.com/Keyrun1227/SchoolOS-AI-Assessment-Agent.git
cd SchoolOS-AI-Assessment-Agent
```

### 2. Set Up the Backend

Create and activate a virtual environment.

**Windows:**

```bash
python -m venv .venv
.venv\Scripts\activate
```

**macOS / Linux:**

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r backend/requirements.txt
```

Configure required environment variables using `.env.example` and the backend documentation. Never commit secrets or production credentials.

Use the startup command documented for the current repository version. The FastAPI entry point is `backend/app/main.py`; confirm the required working directory and configuration first.

### 3. Set Up the Frontend

Open another terminal:

```bash
cd frontend
npm install
```

Configure the API base URL using the supported environment variable:

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

Use the actual backend port configured for your environment.

Start the development server:

```bash
npm run dev
```

### 4. Open SchoolOS AI

- **Live application:** https://schoolos-ai-0z1k.onrender.com/
- **Sample-data demo:** https://keyrun1227.github.io/SchoolOS-AI-Demo/

Live availability and functionality depend on the current deployment configuration.

## 🧪 Testing and Verification

### Backend Tests

```bash
pytest backend/tests -v
```

### Frontend Typecheck

```bash
cd frontend
npm run typecheck
```

### Frontend Production Build

```bash
npm run build
```

A successful build does not independently prove security, data isolation, download correctness, or production readiness.

Important verification areas include:

- Login, logout, and session expiry.
- Role-based and school-level authorization.
- Assessment creation and marks validation.
- Topic analysis and revision recommendations.
- Retest linkage and result comparisons.
- Authorized downloads and unauthorized-request rejection.
- Database persistence and backup/restore.
- Responsive layouts and keyboard accessibility.
- Learning Expedition progression and fictional-data isolation.

Record actual results for the version being released.

---

## 🔒 Security and Privacy

- Keep API keys and secrets on the server.
- Enforce authorization in backend endpoints.
- Restrict parent access to explicitly linked children.
- Restrict students to permitted personal records.
- Prevent cross-school data access.
- Protect reports and downloads.
- Separate public previews from real school records.
- Exclude private data and credentials from source archives.
- Use synthetic data for demonstrations and isolated tests.

**Do not use the platform for real student records until authentication, authorization, data isolation, persistence, and deployment security have been adequately verified.**

## 🚀 Deployment

Before deploying an updated version:

1. Preserve the current working release.
2. Review source changes and environment variables.
3. Run backend tests and the frontend production build.
4. Verify authentication and protected downloads.
5. Test academic workflows using isolated data.
6. Confirm database persistence and recovery.
7. Test role-based access and public demo isolation.
8. Deploy through the intended release process.
9. Verify the deployed application and retain a rollback option.

A local source update does not automatically update the live website.
